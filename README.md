# QQQ Opening Range Breakout Simulator

A TypeScript command-line project for exploring an opening range breakout
strategy with Alpaca market data. It includes historical replay, a recent-bar
scan, and an optional filter based on recorded simulated outcomes.

All fills are simulated locally. The project reads market data and does not
submit orders to a brokerage account.

## Features

- Long-only signals using a 30-minute opening range and 15-minute bars.
- Configurable symbol, share quantity, quantity ceiling, and replay lookback.
- Historical replay with trade summaries and simulated drawdown reporting.
- A CSV ledger and a narrow-range loss-pattern filter.
- A single-pass scan of recent bars; no background scheduler is included.

## Setup

Requires Node.js 18 or newer and npm. Run commands from the repository root.

```sh
npm ci
```

Copy `.env.example` to `.env`:

```powershell
# PowerShell
Copy-Item .env.example .env
```

```sh
# macOS / Linux
cp .env.example .env
```

Uncomment and set `ALPACA_API_KEY` and `ALPACA_SECRET_KEY` in `.env`, or provide
them through environment variables. The market-data commands require valid
Alpaca credentials with access to the requested data feed.

If credentials are absent, `src/market.ts` also checks `~/.alpaca-mcp.env`.
Set `ALPACA_ENV_FILE` to use a different fallback file. Leave the credential
lines commented out when using this fallback: explicitly empty environment
variables are not overwritten by dotenv. Existing process environment values
take precedence over files.

`.env`, credential files, and generated ledgers are excluded from Git. The
example file contains no credentials.

## Commands

| Command | Behavior |
| --- | --- |
| `npm run build` | Type-check the source without emitting JavaScript or accessing market data. |
| `npm run scan` | Fetch recent bars, reconstruct strategy state, and report the latest signal. |
| `npm run replay:raw` | Replay historical bars without the memory filter; append simulated outcomes to the ledger. |
| `npm run replay:memory` | Replay historical bars with the ledger-based filter; append outcomes and skipped entries. |
| `npm run memory:reset` | Clear the local ledger and remove generated lessons. |

The scan and replay commands make market-data requests. `memory:reset` removes
local simulation history; copy the `data/` folder first if you need to retain it.

## Configuration

Runtime options are read in `src/config.ts`.

| Variable | Default | Meaning |
| --- | --- | --- |
| `BOT_SYMBOL` | `QQQ` | Symbol to request and evaluate. |
| `BOT_QUANTITY` | `10` | Shares per simulated fill. |
| `BOT_MAX_POSITION` | `20` | Per-signal quantity ceiling. |
| `BOT_REPLAY_DAYS` | `60` | Calendar days of historical data to request. |

Numeric settings must be finite and positive. If quantity exceeds the ceiling,
the risk check skips the signal. The bar size is fixed at `15Min`; changing it
also requires updating the session constants in `src/strategy.ts`.

`ALLOW_LIVE_TRADING=true` is rejected at startup. Live order execution is not
implemented.

## Strategy and simulation

The strategy builds the opening range from bars starting between 09:30 and
10:00 in `America/New_York`. After the range, a close above its high produces
a BUY signal, with at most one entry per day. An existing position produces a
SELL signal on a close below the range low or on the bar starting at 15:45.

Fills use the signal's close price and configured quantity. Replay starts its
reporting equity at $100,000 and stops approving new entries if realized
simulated drawdown reaches 25%. That drawdown check applies only within one
replay run, and it is not evaluated by `scan`.

## Ledger and memory filter

Runtime files are created under `data/`:

- `ledger.csv`: appended BUY, SELL, and SKIP records, including mode and PnL.
- `learnings.md`: descriptive observations generated by raw replay when the
  implemented repeated-loss condition is met.

The filter groups completed simulated trades by symbol. It needs at least
five ranged trades and at least two losses with an opening-range width below
the median. A new BUY below that median is then skipped. The filter reads the
CSV ledger, not the prose in `learnings.md`.

These files are per-user output and are not included in the repository.

## Current limitations

- Fills omit commissions, spreads, slippage, liquidity, and execution delay.
  Reported PnL is simulated and is not brokerage performance.
- The session logic assumes a full 09:30–16:00 trading day. It does not load an
  exchange calendar or handle early closes, missing closing bars, or incomplete
  current bars explicitly. A first entry on the final bar can remain open.
- `scan` reconstructs state from a bounded recent-bar window. It does not
  persist a broker position or deduplicate repeated scans of the same bar.
- Replay appends to existing history without deduplication or a training/test
  split. Reusing overlapping windows can count the same simulated outcomes
  more than once. Memory replay can also read outcomes dated after the bar it
  is evaluating, so its results are not an out-of-sample validation.
- Drawdown uses realized closed-trade PnL, not mark-to-market equity. Open
  positions at the end of the fetched window are not forced closed by replay.
- Data availability and API errors depend on the provider and account. No
  fallback market data is bundled.

The source can be checked offline with `npm run build` after dependencies are
installed. Market-data access and simulation output require separate runtime
verification with your own configuration.
